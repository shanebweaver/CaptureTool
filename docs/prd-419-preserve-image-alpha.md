# PRD: Preserve Image Alpha Through Rendering and PNG Export

- Issue: [#419](https://github.com/shanebweaver/CaptureTool/issues/419)
- Architecture finding: `ARCH-14`
- Severity: Medium
- Status: Implemented
- Affected features: `IMG-08`, `IMG-12`, `IMG-14`, `IMG-15`

## Summary

The shared Win2D image renderer must preserve transparent and partially transparent pixels from source images and image effects. PNG exports must retain that alpha channel so imported transparent images, chroma-key output, foreground extraction, and object extraction remain transparent.

## Problem

The renderer initially clears its output surfaces to transparent, but `DrawImage` clears the entire intermediate drawing session to opaque white immediately before drawing every normal or chroma-keyed image. Source-over composition then turns transparent source pixels into opaque white pixels. The same white clear also defeats alpha produced by the chroma-key processor.

Foreground and object extraction intentionally encode their masks in the alpha channel of PNG results. Once those results enter the shared renderer, they follow the same normal-image path and are flattened onto white during preview and export.

## Goals

1. Preserve source-image alpha through the shared render pipeline.
2. Preserve alpha generated by chroma key.
3. Preserve transparent extraction results when they are rendered and exported as PNG.
4. Keep transparency visible in the editor against a presentation-only background.
5. Add pixel-level regression coverage at the PNG exporter boundary.

## Non-goals

- Changing foreground or object extraction model behavior.
- Changing chroma-key color matching, tolerance, softness, or GPU fallback behavior.
- Adding a new checkerboard asset or exporting a checkerboard background.
- Defining alpha behavior for output formats that cannot represent transparency.
- Changing crop, orientation, scaling, annotation, or print behavior.

## Functional requirements

### Alpha-preserving composition

1. Image drawing must use source-over composition without first replacing the render surface with opaque white.
2. Fully transparent source pixels must remain fully transparent in PNG output.
3. Partially transparent source pixels must retain their alpha in PNG output.
4. Chroma-keyed pixels must retain the alpha produced by the chroma-key processor.
5. Drawing an image must not erase content already composed into the render surface.

### Preview behavior

1. The render surface remains transparent where the image is transparent.
2. The existing themed editor background remains presentation-only and can show through the transparent Win2D canvas.
3. Presentation background pixels must not be written into exported PNG files.

### Extraction compatibility

Foreground and object extraction results require no special renderer branch. Both are transparent PNG image drawables, so preserving alpha for a normal image source preserves their mask output through preview and PNG export.

## Reliability requirements

- Missing source images continue to fail explicitly.
- The renderer continues to clear each new output surface to transparent before composing drawables.
- Chroma key continues to use its existing GPU path with CPU fallback.
- Rendering owns and disposes temporary Win2D resources as before.

## Test plan

Add end-to-end exporter pixel tests for:

- a normal transparent PNG containing fully and partially transparent pixels, covering imported images and extraction outputs;
- a chroma-keyed PNG containing a keyed pixel and a retained non-keyed pixel;
- the existing missing-source failure path.

Run all non-UI test projects and build the WinUI x64 Debug project.

## Acceptance criteria

- [x] Normal transparent PNG sources retain fully and partially transparent pixels after export.
- [x] Chroma-keyed pixels are transparent in PNG output while non-keyed pixels remain opaque.
- [x] Foreground and object extraction PNG alpha survives the shared normal-image render path.
- [x] The editor background remains presentation-only and is not exported.
- [x] Existing failure behavior remains explicit and recoverable.
- [x] Existing non-UI tests pass and the WinUI x64 Debug project builds.

## Rollout

No migration or feature flag is required. The corrected composition behavior applies to image preview, PNG export, clipboard rendering, and downstream edit operations that use the shared renderer.
